# Freshservice Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: агент service
desk / ITSM-администратор Freshservice.

## 1. Credential type
HTTP Basic Auth: API key аккаунта как username, любая строка как пароль — паттерн
Freshworks (тот же, что у уже существующего freshdesk-connector в портфеле).

## 2. Идеальный флоу (без ограничений SDK)
1. **Домен + API-ключ единой формой** — поле домена с плейсхолдером
   `acme.freshservice.com`, чтобы сразу было понятно, что нужен именно поддомен, а не
   полный URL.
2. **Проверка через реальный запрос** (`GET /api/v2/agents/me`) перед сохранением —
   пользователь сразу узнаёт, если ключ неверный, а не после первой команды.
3. **Health snapshot сразу после подключения** — открытые тикеты/проблемы/изменения,
   чтобы не показывать пустой экран.
4. **Явное объяснение unified Ticket model** — Freshservice объединяет Incident и
   Service Request в одну сущность "Ticket" с полем `type`; без этого объяснения
   пользователь будет искать отдельный "Incidents" список и не найдёт.
5. **Понятные ошибки авторизации** — при 401 явно предложить перепроверить API-ключ
   в Profile Settings Freshservice, а не показывать generic ошибку.
